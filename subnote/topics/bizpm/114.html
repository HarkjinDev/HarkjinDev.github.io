[하위] 3-1. 클라우드 재해복구 (Cloud Disaster Recovery, Cloud DR)

  • 정의: 클라우드 자원을 활용해 재해 발생 시 시스템과 데이터를 복구하는 기술
  • 키워드: 재해복구, 복구목표시간(RTO), 복구목표시점(RPO), 백업·복원, 대기 시스템, 다중 리전, 장애 전환
  • 분류: 클라우드 컴퓨팅 / IT 서비스 연속성 / 재해복구
  • 클라우드 DR 4대 유형:
    DR 유형주요 구성·동작 방식RPORTO운영 비용
    Backup & Restore백업 데이터로 인프라 재구성·복구수 시간수 시간~24시간낮음
    Pilot Light핵심 자원만 상시 유지, 장애 시 확장수 분수십 분~수 시간낮음~중간
    Warm Standby축소된 운영 환경 상시 가동·동기화수 초~수 분수 분중간~높음
    Multi-Site (Active/Active)복수 리전 동시 운영·트래픽 분산0에 근접0에 근접높음
  • DR 유형별 구성 및 운영 특성:
    구분Backup & RestorePilot LightWarm StandbyActive/Active
    DR 인프라장애 시 구성핵심 자원 유지축소 환경 운영전체 환경 운영
    데이터 복제주기적 백업지속적 복제지속적 복제실시간·준실시간
    평상시 서비스주 시스템만주 시스템만주 시스템만양쪽 동시 제공
    장애 복구백업 복원자원 확장·전환확장·트래픽 전환정상 리전으로 전환
    복구 복잡도복원 절차 중심자원 재구성 필요용량 확장 필요데이터 충돌·분산 관리
    적용 대상비핵심 업무일반 업무중요 업무핵심·상시 서비스
  • 클라우드 DR 수행 절차:
    단계수행 절차주요 활동핵심
    1. 업무 분석BIA업무 중요도·중단 영향·RTO/RPO 정의복구 목표
    2. 전략 설계DR Strategy복구 유형·리전·복제 방식 선정복구 전략
    3. 환경 구축DR Provisioning백업·복제·대기 인프라 구성복구 환경
    4. 장애 복구Failover장애 감지·DR 전환·서비스 재개서비스 복구
    5. 복구 검증DR Testing정합성·RTO/RPO·업무 정상화 확인복구 실효성
    6. 지속 개선DR Optimization모의훈련·원인 분석·복구 절차 개선복구 최적화
  • 클라우드 DR 주요 기술:
    구분주요 기술활용 목적핵심
    데이터 보호Snapshot, Backup데이터 복원백업·복구
    데이터 동기화DB Replication, CDC리전 간 데이터 복제정합성 확보
    장애 전환DNS Failover, GSLBDR 환경으로 트래픽 전환자동 전환
    인프라 자동화Terraform, IaCDR 환경 자동 재구성복구 자동화
    컨테이너 복구Kubernetes, GitOps클러스터·워크로드 재배포서비스 복원
    복구 검증DR Drill, Chaos Engineering장애·복구 시나리오 검증복구 신뢰성
  • 클라우드 DR 적용 시 고려사항:
    구분주요 한계대응 방안핵심
    복구 목표과도한 RTO·RPO 요구로 비용 증가BIA 기반 업무별 차등 설계목표 적정성
    데이터 정합성비동기 복제 지연·데이터 손실복제 상태 감시·정합성 검증데이터 일관성
    시스템 의존성DB·네트워크·인증체계 복구 누락의존성 분석·통합 복구복구 완전성
    비용 최적화대기 자원·리전 간 전송 비용업무별 DR 유형 차등화비용 효율
    복구 검증DR 구성만 존재하고 실제 복구 실패정기 모의훈련·자동 검증복구 실효성
    보안 위험랜섬웨어·오염 데이터의 복제 확산불변 백업·격리 계정·복구 시점 검증복구 안전성
  • 인사이트: BIA 기반 RTO·RPO와 업무 중요도에 따라 DR 유형을 차등 적용하고, IaC·자동 Failover로 복구시간을 최소화해야 함. 특히 다중 리전 장애와 랜섬웨어를 고려한 격리 백업·정기 복구훈련으로 실질적인 업무 연속성을 검증해야 함.
