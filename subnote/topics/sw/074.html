[하위] 3-3. CQRS 패턴

  • 정의: 데이터 변경(Command)과 데이터 조회(Query) 책임을 분리하여 각각 독립적인 모델과 저장소를 사용하는 디자인 패턴
  • 키워드: 책임 분리, 성능 최적화, Command Model, Write DB + Read DB, Query Model, CDC
  • CQRS 패턴 기술요소
    구분기술요소설명핵심
    CommandCommand Model데이터를 등록·수정·삭제하는 변경작업데이터 변경작업
    Write DBDB에서 데이터변경(insert·update·delete)쓰기 전용DB
    DDD복잡한 쓰기모델의 비즈니스로직 도메인 설계
    Event Sourcing상태변경 이벤트를 순차적으로 저장이벤트 저장
    QueryQuery Model데이터를 조회하는 읽기작업데이터 조회작업
    Read DBDB에서 데이터를 가져오는 select읽기 전용DB
    Redis인메모리 캐시로 응답속도 극대화캐시 가속
    Elasticsearch복잡한 조건검색 쿼리를 고속처리검색엔진 활용
    데이터 동기화Event Bus데이터변경 이벤트를 비동기 전달비동기 이벤트전달
    Kafka, RabbitMQWrite DB 변경사항을 Read DB로 전달메시지큐 동기화
    CDC두 저장소간 데이터 균형을 맞추는 변경감지변경데이터 캡처
  • CRUD와 CQRS의 비교
    비교 항목CRUDCQRS
    모델단일 모델읽기 모델 / 쓰기 모델
    데이터베이스단일 DBWrite DB + Read DB
    성능읽기/쓰기 경쟁변경/조회 각각 최적화
    확장성제한적독립적 Scale-out
    데이터 일관성Strong ConsistencyEventual Consistency
    적용 환경일반 업무 시스템MSA, EDA, 대용량 서비스
  • 인사이트: MSA, EDA, Event Sourcing 기반 시스템에서 대규모 트래픽 처리와 데이터 정합성 확보를 위한 핵심 설계 기법으로 활용
