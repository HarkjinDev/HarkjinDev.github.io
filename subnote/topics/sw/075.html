[하위] 3-4. CDC(Change Data Capture)와 이벤트 소싱(Event Sourcing)

  • 정의: 데이터 변경사항의 추적과 이벤트 기록을 통한 상태 관리 방식 비교
  • 키워드: 변경 데이터 캡처, 이벤트 저장소, 변경 로그, 상태 재구성, 트랜잭션 로그, 이벤트 기반 아키텍처
  • 분류: 소프트웨어 아키텍처
  • CDC와 이벤트 소싱 비교:
    구분CDC (Change Data Capture)이벤트 소싱 (Event Sourcing)
    개념DB의 데이터 변경사항 추출·전파상태 변경 이벤트를 원본으로 저장
    목적데이터 변경 감지·동기화이벤트 기반 상태 관리·이력 보존
    데이터 원천기존 데이터베이스이벤트 저장소 (Event Store)
    저장 단위INSERT·UPDATE·DELETE 변경 내역업무 이벤트 (주문생성·결제완료 등)
    처리 시점DB 변경 발생 후 캡처업무 처리 시 이벤트 기록
    구현 방식트랜잭션 로그·트리거·폴링이벤트 기록·재생·프로젝션
    데이터 구조변경 전후 데이터·메타데이터이벤트 유형·내용·발생시각
    상태 관리DB의 현재 상태 중심이벤트 누적으로 현재 상태 재구성
    이력 관리캡처·보존 범위 내 변경 이력이벤트의 장기·불변 이력 관리
    주요 기술Debezium, Kafka Connect, Oracle GoldenGateEventStoreDB, Axon Framework
    적용 분야DB 동기화·ETL·실시간 복제금융거래·주문관리·감사 추적
    주요 한계업무 의미 파악 어려움·로그 의존성이벤트 스키마 진화·재생 복잡성
    핵심데이터 변경 전파이벤트 기반 상태 재구성
  • CDC 주요 구현 방식:
    구현 방식주요 원리장점한계
    로그 기반DB 트랜잭션 로그 분석낮은 DB 부하·변경 순서 추적DB 로그 접근 필요
    트리거 기반변경 시 트리거 실행변경 즉시 수집DB 쓰기 부하 증가
    폴링 기반변경 시각·버전 주기적 조회구현 간단삭제 감지·변경 누락 가능
  • 이벤트 소싱 핵심 구성요소:
    구성요소주요 기능핵심
    명령 (Command)업무 변경 요청·검증변경 요청
    이벤트 저장소 (Event Store)발생 이벤트 순차·불변 저장이력 보존
    재생 (Replay)이벤트 재적용으로 상태 복원상태 재구성
    투영 (Projection)이벤트를 조회용 데이터 모델로 변환읽기 모델
  • 인사이트: 기존 DB 기반 시스템의 실시간 데이터 연계에는 CDC를, 변경 이력과 상태 재구성이 중요한 업무에는 이벤트 소싱을 적용해야 함. 두 기술을 Outbox 패턴·Kafka와 연계할 경우 이벤트 전달의 정합성과 시스템 확장성을 함께 확보할 수 있음.
