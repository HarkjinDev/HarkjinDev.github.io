14. AI 에이전트 신원 (AI Agent Identity)

  • 정의: AI 에이전트에 고유한 디지털 신원을 부여하고, 신뢰성과 책임성을 확보하는 비인간 신원(Non-Human Identity, NHI) 관리 기술
  • 키워드: Agent Identity, NHI, IAM, OAuth 2.0, OIDC, RBAC, ABAC, Zero Trust, Least Privilege, Delegated Authorization, Identity Lifecycle, Agent-to-Agent(A2A), MCP
  • 분류: AI 보안
  • 핵심 구성요소:
    구성요소주요 기능핵심
    신원 식별 (Identification)에이전트별 고유 ID 발급·등록고유 신원
    신원 인증 (Authentication)인증서·토큰 기반 신원 검증신뢰성 검증
    권한 관리 (Authorization)RBAC·ABAC 기반 접근권한 부여최소 권한
    위임 관리 (Delegation)사용자·에이전트 간 권한 위임 통제권한 범위
    감사 추적 (Audit)API 호출·도구 실행·행위 이력 기록책임 추적
    생명주기 관리 (Lifecycle)신원 발급·변경·회수·폐기신원 거버넌스
  • AI 에이전트 신원 주요 보안 기술:
    기술주요 기능핵심
    OAuth 2.0범위 제한 액세스 토큰·위임 인가위임·인가
    OIDCID Token 기반 신원 인증신원 검증
    mTLS상호 인증서 기반 통신 인증상호 인증
    RBAC역할별 접근권한 제어역할 기반 통제
    ABAC속성·환경·작업 맥락 기반 권한 제어동적 접근통제
    PAM고위험·특권 작업 권한 통제특권 관리
    Short-lived Token단기 토큰 발급·만료·재발급자격증명 보호
    Zero Trust요청별 신원·권한·상황 검증지속적 검증
  • AI 에이전트 신원 보안 위협 및 대응:
    보안 위협주요 위험대응 방안
    신원 위장 (Spoofing)타 에이전트·사용자 사칭강력한 인증·상호 인증
    권한 상승 (Privilege Escalation)허용 범위 초과 작업 수행최소 권한·RBAC·ABAC
    토큰 탈취 (Token Theft)인증정보 유출·재사용단기 토큰·토큰 바인딩
    프롬프트 인젝션악성 명령으로 권한 오남용정책 기반 실행 검증
    과도한 자율성무단 변경·삭제·외부 전송HITL·승인 기반 실행
    에이전트 확산 (Agent Sprawl)미관리 에이전트·유휴 권한 증가신원 인벤토리·정기 권한 검토
    책임 추적 부재에이전트 행위 주체 불명확Agent ID·위임자·실행 로그 연계
  • AI 에이전트 신원 도입 고려사항:
    구분고려사항대응 방안
    신원 관리에이전트 생성·증가에 따른 관리 복잡성중앙 신원 등록·인벤토리 관리
    권한 통제사용자 위임·에이전트 자체 권한 혼재권한 분리·작업별 최소 권한
    자격증명API Key·Secret 유출 위험단기 토큰·Secrets Manager
    신뢰 검증에이전트 간 호출 신뢰성 부족상호 인증·토큰 검증
    운영 통제AI의 비결정적 실행·오작동HITL·정책 엔진·실행 제한
    감사·책임성작업 실행 주체·책임자 불명확사용자·Agent ID·작업 ID 연계
  • 인사이트: AI 에이전트 신원은 기존 인간·서비스 계정 중심 IAM을 자율적 비인간 신원으로 확장하는 핵심 보안 기술임. Agentic AI 환경에서는 단순 인증을 넘어 에이전트의 고유 신원, 사용자 위임 관계, 작업별 권한 및 실행 이력을 통합 관리해야 하며, 프롬프트 인젝션에 의한 권한 오남용을 방지하기 위해 LLM의 판단과 실제 권한 집행을 분리해야 함. 특히 Zero Trust 기반 최소 권한, 단기 토큰, 정책 기반 인가, HITL 및 감사 추적을 결합하여 에이전트의 자율성을 보장하면서도 통제 가능한 신뢰 체계를 구축하는 것이 중요함.
