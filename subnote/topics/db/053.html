3. 분산 데이터베이스 (Distributed Database, DDB)

  • 정의: 네트워크로 연결된 여러 노드에 데이터를 분산 저장·관리하는 데이터베이스
  • 키워드: 위치/복제/병행/분할/장애 투명성, 분할/복제/할당 전략, 분산 트랜잭션, 일관성, 샤딩
  • 분류: 분산DB/파티셔닝
  • 데이터 분산 방식: <분복할>
    구분분산 방식주요 원리핵심
    분할수평 분할 (Horizontal)행(Row) 단위 데이터 분할샤딩
    수직 분할 (Vertical)열(Column) 단위 데이터 분할속성 분리
    혼합 분할 (Hybrid)수평·수직 분할 조합복합 분할
    복제전체 복제 (Full)모든 대상 노드에 전체 데이터 복제가용성 확보
    부분 복제 (Partial)일부 데이터만 선택적 복제자원 최적화
    비복제 (No Replication)데이터 복제본 없이 원본만 유지저장 효율
    할당비중복 할당 (Non-redundant)분할 데이터를 단일 노드에 배치저장 효율
    중복 할당 (Redundant)동일 분할 데이터를 복수 노드에 배치장애 대응
  • 분산 데이터베이스 투명성: <위복병분장>
    구분투명성주요 내용핵심
    데이터위치 투명성데이터 저장 위치 은닉위치 독립
    분할 투명성데이터 분할 구조 은닉분할 독립
    복제 투명성복제본 존재·위치 은닉복제 독립
    운영장애 투명성노드 장애·복구 과정 은닉장애 대응
    병행 투명성동시 트랜잭션 간 간섭 제어동시성 보장
  • 분산 데이터베이스 일관성 모델:
    일관성 모델주요 내용핵심
    강한 일관성 (Strong Consistency)완료된 쓰기 이후 최신 데이터 조회 보장최신 데이터
    최종 일관성 (Eventual Consistency)갱신 중단 시 복제본이 최종적으로 수렴비동기 동기화
    인과 일관성 (Causal Consistency)인과관계가 있는 연산의 순서 보장인과 순서
    세션 일관성 (Session Consistency)동일 세션에서 정의된 읽기·쓰기 보장 제공세션 정합성
  • 분산 트랜잭션 주요 기술:
    구분기술주요 원리핵심
    원자성2PC (2-Phase Commit)준비·확정 2단계로 분산 커밋원자적 커밋
    3PC (3-Phase Commit)중간 사전 확정 단계 추가블로킹 완화
    합의Raft리더 선출·로그 복제로 합의분산 합의
    Paxos다수 노드의 합의 기반 값 결정상태 일치
    업무 보상Saga Pattern로컬 트랜잭션·보상 작업 연결보상 트랜잭션
  • 중앙집중형 DB와 분산 DB 비교:
    구분중앙집중형 DB분산 DB
    데이터 저장단일 시스템 중심다중 노드 분산 저장
    확장 방식수직 확장 중심수평 확장 중심
    장애 대응별도 이중화 필요복제·장애 조치 활용
    데이터 정합성상대적으로 관리 용이노드 간 동기화 필요
    트랜잭션단일 DB 트랜잭션분산 트랜잭션 조정
    관리 복잡도상대적으로 낮음네트워크·복제·합의 관리
    주요 목적단일 환경 데이터 관리확장성·가용성·분산 처리
  • 분산 데이터베이스 적용 시 고려사항:
    구분주요 한계대응 방안핵심
    분할 전략데이터 편중·핫스팟샤드 키 최적화·리밸런싱부하 균등화
    복제 관리복제 지연·데이터 불일치동기화 정책·복제 상태 감시정합성 확보
    일관성가용성과 일관성 충돌업무별 일관성 수준 선택CAP 고려
    트랜잭션분산 커밋 지연·블로킹2PC·Saga 등 선택 적용트랜잭션 안정성
    장애 대응네트워크 단절·노드 장애복제·자동 장애 조치·합의내결함성 확보
  • 인사이트: 업무별 정합성 요구사항에 따라 CP·AP 성향과 일관성 수준을 선택하고, 샤드 키·복제·분산 트랜잭션 전략을 함께 설계해야 함. 특히 네트워크 분할과 노드 장애를 가정한 복구·재처리 검증을 통해 실질적인 가용성을 확보하는 것이 중요함.
