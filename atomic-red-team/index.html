MITRE ATT&CK 기법 실행 → 로그 수집 및 탐지 평가 → Sigma 룰 검증을 통해 탐지 격차와 운영상 개선점을 분석한 실험 프로젝트입니다.

Windows 10 VM (Sysmon + Wazuh Agent) → Docker Wazuh 4.14.5

접근 방식

Atomic Red Team의 ATT&CK 기법 실행을 자동화하고, 각 기법이 SIEM에서 어떻게 탐지되는지(혹은 안 되는지) 체계적으로 분석하는 파이프라인을 구성했다.

① Invoke-AtomicTest 로 기법 실행 ② Sysmon → Wazuh Agent → Docker Wazuh 로 로그 수집 ③ 내장 룰이 잡는가 / 정확한가 / 격차가 있는가 평가 ④ 격차가 있으면 Sigma 룰 작성 (근거·설계판단 주석) ⑤ 실측 로그로 룰 조건 검증 ⑥ Python 배치로 다중 기법 자동 실행 → 커버리지 집계 → Navigator layer 생성

핵심 발견

내장 룰의 T1087 오분류 편향

오분류(PARTIAL)로 판정된 기법을 모아 보면, 4건 전부가 T1087(Account Discovery)로 잘못 태그됐다. Wazuh 내장 룰 92032가 "cmd의 자식 프로세스"를 기법 종류와 무관하게 T1087로 태그하는 구조적 편향이, 여러 기법에 걸친 배치 실행으로 정량 확인됐다.

오탐이 실제 위협보다 높은 심각도로 잡힌다

PowerShell이 정상적으로 만드는 임시파일(__PSScriptPolicyTest)이 level 15(최고)로, 배치 중 27회 반복 발동했다. 정작 실제 정찰 도구(SharpHound)는 level 6으로 더 낮았다. 오탐 필터링(Sigma filter)이 탐지 엔지니어링의 절반임을 실측으로 확인했다.

"로그가 없다"의 세 가지 원인

탐지 실패로 보이는 상황은 원인이 다르다 — 검색어 불일치(T1547.001, 실제론 로그 존재), 예방 차단(T1218.011, Defender가 실행 자체 차단), 로그 소스 미수집(T1070.004, Sysmon EID23 꺼짐). 탐지룰보다 로그 소스 커버리지 점검이 선행되어야 한다.
